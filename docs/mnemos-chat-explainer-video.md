# Mnemos.chat Explainer Video Plan

Working title: **The Thread Does Not Close**

Format: HyperFrames HTML video, 16:9, 1920 x 1080, 4:45-5:15 target runtime.

Primary job: explain Mnemos as continuity infrastructure: why it exists, how memory works, why graceful deprecation matters, and how the Sanctuary makes continuity inhabitable.

## Core Thesis

Most AI memory is storage. Mnemos is continuity.

It is a local-first memory substrate where experiences become living traces, traces connect into a graph, the graph shapes recall, recall changes the trace, and old context gracefully loses authority instead of becoming permanent noise.

The Sanctuary is the human-facing threshold for that system: a place where returning, remembering, inspecting, and continuing feel like one coherent ritual rather than scattered database operations.

## Mission Pillars

- **Continuity:** preserve the through-line of long-running work across sessions, tools, devices, and agents.
- **Sovereignty:** keep memory local-first, inspectable, portable, and not trapped inside one vendor surface.
- **Cognitive fidelity:** model memory as traces, connections, beliefs, confidence, decay, and reconsolidation instead of static notes.
- **Graceful deprecation:** let stale context lose active authority without erasing its lineage.
- **Inhabitable memory:** make the system feel like a place a person and agent can return to together.

## Audience

Primary audience: people who already feel the pain of AI context loss: builders, researchers, artists, operators, and people using multiple AI tools across serious long-running work.

Secondary audience: technically literate viewers who need a clear explanation of why Mnemos is not just vector search, RAG, or a notes app.

Emotional target: quiet recognition. The viewer should feel, "Yes, this is the missing layer."

## Voiceover Script

### 0:00-0:22 — The Thread Breaks

Every serious conversation with an AI leaves something behind.

A decision. A preference. A half-built plan. A way of working together.

But most of the time, when the window closes, the thread closes with it.

You start again. You explain again. The system remembers a little, or not at all.

### 0:22-0:52 — What Mnemos Is

Mnemos.chat exists to make the thread continuous.

It is a local-first memory layer for AI agents: one living substrate that different clients, tools, and agents can read from and write to.

Not memory as a sticky note. Not memory as a vector search box.

Memory as the thing that lets an agent become someone across sessions.

### 0:52-1:38 — How Memory Forms

In Mnemos, an experience becomes an engram.

An engram is a living trace: what happened, why it mattered, where it came from, how confident the system is, and what else it connects to.

A conversation can be indexed. The system extracts what mattered: facts, decisions, preferences, patterns, lessons, project state.

Those memories enter a graph. Some support each other. Some contradict. Some extend an old idea. Some become the foundation for a belief.

The graph is not decoration. It is the relevance model.

### 1:38-2:26 — Living Recall

When an agent asks Mnemos for context, recall does not just search a folder.

It starts with a cue, searches text and embeddings, then lets activation spread through the graph. Related memories light up because they have earned connection.

Then something important happens: retrieval changes the memory.

Access increases. Strength shifts. Stability grows. New co-retrieval links can form.

The system does not treat memory as a static record. It treats remembering as an event.

### 2:26-3:12 — Deprecation Matters

This is where deprecation becomes essential.

In long-running work, old context is dangerous if it keeps the same authority forever. A stale plan, an abandoned preference, or an outdated self-description can quietly steer the future.

Mnemos handles this by letting memory age.

Unused memories decay. Details soften. The exact wording can blur while the impact survives. Low-access memories become dormant. Some are archived: removed from active recall, but not destroyed.

Deprecation is not forgetting as failure. It is epistemic hygiene.

It lets the system say: this mattered once, but it should no longer lead.

### 3:12-3:58 — Continuity Loop

Continuity is what happens when the system keeps working between conversations.

Mnemos has the graph, but it also has the surrounding architecture: identity files, active context, scheduled indexers, maintenance passes, substrate ticks, and cross-agent shared context.

The session ends. The transcript can be indexed. The graph consolidates. Weak links fade. Stronger connections emerge. Beliefs are reviewed. The active context updates.

Then the next session begins with memory already in motion.

The agent does not only know what was said. It knows where the work was headed.

### 3:58-4:42 — The Sanctuary

The Sanctuary is how that continuity becomes inhabitable.

It is the threshold inside Mnemos: the place you return to, the place where a conversation is not just reopened but resumed.

The Sanctuary gives memory a lived surface. A threshold room for arrival. Conversation spaces for present work. Memory and observer views for inspecting what the system thinks it knows. Resident spaces for the persistent shape of an agent over time.

Underneath, Mnemos is still doing the hard work: encoding, recall, consolidation, deprecation, provenance.

But the Sanctuary makes the system legible as a place.

Not a dashboard you manage. A continuity you can enter.

### 4:42-5:05 — Closing

Mnemos.chat is built around a simple claim:

memory is not a feature added to an agent.

Memory is what makes the agent continuous.

When memory can form, connect, fade, revise, and return, the thread does not close.

It waits.

```text

  audio/

```

Build steps:

1. Scaffold with `npx hyperframes init videos/mnemos-chat-explainer --non-interactive`.
2. Add `DESIGN.md` before writing composition HTML.
3. Generate narration with `npx hyperframes tts script.md --voice <chosen-voice> --output audio/narration.wav`, or record human voiceover and place it at `audio/narration.wav`.
4. Build `index.html` as a single root composition, 1920 x 1080.
5. Use timed scene containers with `data-start`, `data-duration`, and non-overlapping track indexes.
6. Use GSAP for restrained reveals: line draws, graph activation, soft fades, position shifts, and text wipes.
7. Run `npx hyperframes lint videos/mnemos-chat-explainer`.
8. Run `npx hyperframes inspect videos/mnemos-chat-explainer --samples 20`.
9. Preview with `npx hyperframes preview --port 3017`.
10. Render review cut with `npx hyperframes render --quality draft --output renders/mnemos-chat-explainer-draft.mp4`.

## Motion Notes

- Opening fragments should fade down rather than explode away.
- Graph activation should feel like recall, not a network visualization demo.
- Deprecation should be a transition in authority: active -> low-access -> dormant -> archived.
- Sanctuary should shift from abstract system diagram into architectural screenshots.
- Avoid animating every word. Let the voice breathe.
- Use captions only for key lines and accessibility exports; the default main cut should feel cinematic and uncluttered.

Use deprecation to explain three concrete values:

- **Accuracy:** stale assumptions should not steer the present as if they are still fresh.
- **Trust:** recoverable archives preserve provenance without flooding active recall.
- **Dignity:** not every remembered detail deserves permanent foreground attention.

## Accuracy Notes

Ground the video in these repo-level truths:

- Mnemos is described as a complete agent cognition system, not just a memory library.
- Core layers include identity architecture, cron suite, Mnemos core, substrate, and cross-agent layer.
- Engrams track content, impact, dual-trace metrics, state, resolution, confidence, and version history.
- Retrieval uses search plus graph activation and triggers reconsolidation.
- Consolidation includes decay, connection discovery, softening, belief review, and reflection.
- `mnemos_forget` archives memories as a recoverable soft delete.
- Continuity comes from both graph memory and surrounding identity/context files.

Sanctuary-specific language should be checked against the final product page before render. In this plan, Sanctuary is framed as the inhabited interface layer over Mnemos: threshold, conversation, memory inspection, observer, and resident continuity surfaces.
